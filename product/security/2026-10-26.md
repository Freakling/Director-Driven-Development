## Findings
### F1 · The Claude Code allow-list lets the agent run any code without a prompt · A01:2025 Broken Access Control · med · B5
- Evidence: `.claude/settings.json:14-19` allows `npm`, `npx`, `pnpm`, `yarn`, `flutter`, `python` and `pip` with any arguments, and lines 34-35 allow WebSearch and WebFetch; the deny list (lines 40-47) covers only `.env`, `*.pem` and `*.key`. The lines come from the App Director template.
- Fails when: `python -c`, `npx <package>` or `pip install <package>` runs arbitrary code with no prompt, which can push, create releases or read credential stores outside the repository, so the "other pushes still prompt" boundary in `tools/work-publish.sh:15-17` and `tools/work-release.sh:16-19` doesn't hold. Prompt injection from a fetched page or framework content is the trigger. This stack uses none of npm, npx, pnpm, yarn or flutter.
- Fix: allow only what this repository runs (`python -m mkdocs`, `python tools/usage.py`, `pip install -r requirements.txt`), drop the rest, deny reads of the gh, git credential and SSH stores, and file the template change in App-Director so an upgrade doesn't restore the lines.

### F2 · The CI build installs unpinned transitive Python packages without hashes · A03:2025 Software Supply Chain Failures · low · B6
- Evidence: `requirements.txt:1-2` pins only mkdocs and mkdocs-material; `.github/workflows/docs.yml:24` installs it, so the packages that render the published site resolve to their newest releases on every run.
- Fails when: a compromised or broken upstream release runs in CI and injects script into the published pages.
- Fix: commit a fully pinned lock with hashes (`pip-compile --generate-hashes`) and install with `--require-hashes`.

### F3 · The docs workflow pins actions by mutable tag · A08:2025 Software or Data Integrity Failures · low · B7
- Evidence: `.github/workflows/docs.yml:19,20,27,44` use four actions by major tag.
- Fails when: a moved or compromised tag runs new code in the deploy job, which holds `pages: write` and `id-token: write`. All four are GitHub-owned, which lowers the risk.
- Fix: pin each action to a commit SHA with the version in a comment, and let Dependabot propose updates.

### F4 · Two paths skip the secrets scan · A07:2025 Authentication Failures · low · B8
- Evidence: the scan runs only in `tools/check.sh:172-180` and the local pre-commit hook; `docs.yml` has no gitleaks step. `tools/work-publish.sh:142` pushes `work/` clone commits to the public framework repositories with no scan from this side.
- Fails when: a credential in a commit made outside the hook, or in a clone's item commit, reaches a public repository.
- Fix: a gitleaks step in `docs.yml`, a scan of `origin/main..HEAD` in the clone before `work-publish.sh` pushes, and GitHub secret scanning push protection.

### F5 · The published site sets no Content-Security-Policy · A02:2025 Security Misconfiguration · low · B9
- Evidence: `mkdocs.yml` has no `theme.custom_dir` and no meta CSP; GitHub Pages can't send custom response headers.
- Fails when: injected content (see F2) or a raw-HTML mistake in a page has no policy to contain it.
- Fix: a `custom_dir` override whose `extrahead` sets a meta CSP that allows the itch.io frame and Material's inline scripts, and an accepted decision naming A02 for the headers Pages can't send.

### F6 · The itch.io iframe has no sandbox · A08:2025 Software or Data Integrity Failures · low · B10
- Evidence: `docs/examples/pksei.md:12` embeds the frame without `sandbox`, `referrerpolicy` or `loading`.
- Fails when: compromised frame content opens popups or navigates the top window with user activation.
- Fix: `sandbox="allow-scripts allow-same-origin allow-popups"`, `referrerpolicy="no-referrer"` and `loading="lazy"`, keeping the link fallback.

### F7 · Two tools reuse a predictable temp folder · A01:2025 Broken Access Control · low · B11
- Evidence: `tools/push-alignment.sh:27,78` and `tools/audit.sh:25-26` build the folder from the process ID and create it with `mkdir -p`; with `--add`, push-alignment writes its TASKS.md copy back (line 154).
- Fails when: on a shared Unix temp folder another user pre-creates it and changes the copy before it's written back. On Windows Git Bash the temp folder is per user.
- Fix: `mktemp -d`, as `work-publish.sh` and `work-release.sh` already do.

### F8 · The work scripts' origin check accepts any host and ignores pushurl · A01:2025 Broken Access Control · low · B12
- Evidence: `tools/work-publish.sh:89-92`, `tools/work-release.sh:118-121` and `tools/work-clones.sh:76-81` accept any origin ending in `/Freakling/<repo>`, and never check `remote.origin.pushurl`.
- Fails when: a tampered clone configuration sends a branch or tag elsewhere while the gh steps target the real repository. It needs local write access to the clone.
- Fix: match the GitHub URL exactly and refuse when a different pushurl is set.

### F9 · The screen-capture tooling has an open version range and no lock file · A03:2025 Software Supply Chain Failures · low · B13
- Evidence: `tools/ui/package.json:9` takes playwright at `^1.50.0` and `tools/ui/.npmrc:2` sets `package-lock=false`.
- Fails when: an install takes whatever release is newest in the range. The tooling is framework-owned and this static site doesn't use it.
- Fix: in App-Director, pin the exact version and commit a lock file, or record why not.
