## Findings
### F1 · The wildcard git allow rules write and read any file without a prompt · A01:2025 Broken Access Control · med · B17
- Evidence: `.claude/settings.json:15-17,21,23-24` allow `git diff *`, `git log *`, `git show *`, `git commit *`, `git stash *` and `git worktree *` with any flags. By git's documented options, `--output=<path>` on `git log`, `git diff`, `git show` and `git stash show` writes to any path, and the allowed `bash tools/check.sh` runs `tools/check.local.sh` and `tools/stacks/none.sh` (`tools/check.sh:243,250-252`), while `git commit` runs `.githooks/pre-commit`. `git diff --no-index /dev/null <path>`, or `git commit -F <path>` then `git log`, prints any file, past the Read deny rules (`settings.json:33-40`); the guard hook matches only `cat`, `head`, `tail`, `less`, `more` and `strings` (`.claude/hooks/guard-commands.sh:38-39`), and its git rules (`:112-128`) don't look at these flags. Selftest section 8 checks code runners only (`selftest.sh:422-431`). App-Director's template has the same rules. Not yet confirmed on this machine.
- Fails when: text injected into a fetched page (WebFetch and WebSearch run without a prompt) or into framework content leads the agent to write `tools/check.local.sh` with `git log --output` and run the check, which then runs code with the director's git and gh credentials and can push or release to the public framework repositories; or `git diff --no-index` prints a credential store into the context, from where WebFetch can send it out.
- Fix: replace the wildcard git rules with the exact forms the procedures use, or deny the flags that write, read outside the repository or run commands (`--output`, `--no-index`, commit `-F` and `--file`, `-O` and `--open-files-in-pager`, `--ext-diff`, `git worktree add`); make selftest section 8 fail on them; carry the change into App-Director's template, as T213 did; confirm each vector first with a harmless write or read in a scratch folder. B14 and B15 are the same class.

### F2 · The pre-commit secrets scan skips Markdown, shell, HTML and the records · A07:2025 Authentication Failures · low · B18
- Evidence: `.githooks/pre-commit:21-27` runs the check, and its staged `gitleaks protect` scan, only when a staged file matches `ts|tsx|js|jsx|mjs|dart|py|json|yaml|yml` or the check's own files; `tools/check.sh:67-71` fingerprints the same set, so `--if-changed`, which the hook and the Stop hook (`.claude/hooks/stop-check.sh:37`) use, reuses an earlier pass after any other change, and the Stop hook skips Markdown-only changes (`:19`). Nearly every file here falls outside the filter: the pages, `overrides/main.html`, `selftest.sh`, the scripts under `tools/`, `requirements.txt`, `frameworks.lock` and `TASKS.md`.
- Fails when: a token pasted into a page, a script or a record is committed (record commits go in without pausing) and pushed with no local scan; CI's full-history scan flags it only once it is in the public repository, which breaks `rules.md` › Secrets ("the pre-commit hook also scans staged changes").
- Fix: an App-Director item, since the files are framework-owned: run the staged gitleaks scan on every commit, whatever is staged, and with stack `none` count every tracked file in the staged filter and the fingerprint.

### F3 · The publish and release pushes follow git push config the scripts don't pin · A01:2025 Broken Access Control · low · B19
- Evidence: `tools/work-publish.sh:242` runs `git push -u origin "$branch"` with no explicit destination; the script checks the branch name (`:133-142`) and origin's URLs (`:108-130`) but not `remote.origin.push` or `push.followTags`. `tools/work-release.sh` pushes its tag the same way. `git tag *` runs without a prompt (`settings.json:22`). The header promises no push to `main` and no `+` refspec (`tools/work-publish.sh:14-17`). Neither setting is on this machine today.
- Fails when: with `push.followTags` on, a mistaken local tag the bundle reaches is pushed to the public framework repository before the director merges anything, and an install that pins `--branch v<version>` takes unreviewed code; or a `remote.origin.push` mapping sends the bundle to `main`. Both go against `product/decisions.md:36` and `:54`.
- Fix: push with `git push --no-follow-tags -u origin "refs/heads/$branch:refs/heads/$branch"`, push the tag with `--no-follow-tags origin "refs/tags/$tag:refs/tags/$tag"`, and refuse when `git config --get-all remote.origin.push` returns anything.

### F4 · This repo's screen-capture tooling still takes an open Playwright range · A03:2025 Software Supply Chain Failures · low · B20
- Evidence: `tools/ui/package.json:9` asks for `^1.50.0`, with `package-lock=false` in `tools/ui/.npmrc:2`. B13's exact pin shipped in App-Director, and its note leaves this repo's copy to the next App-Director upgrade, which no item does yet. Nothing is installed (no `tools/ui/node_modules`), and the site doesn't use the tooling.
- Fails when: `npm install` here takes whatever release is newest in the range, with the Chromium it downloads.
- Fix: upgrade this repo's App Director files to the current release, which brings the exact pin.
